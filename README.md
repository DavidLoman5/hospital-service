# 看診進度 LINE Bot

傳一則 LINE 訊息就能查看診進度，並在快輪到你的時候主動通知你 — 不必守在候診區一直重新整理網頁。也能記下回診日期和慢性處方箋的領藥時間，到時候提醒。

目前支援：中國醫藥大學新竹附設醫院。其他醫院依 [docs/hospitals.md](docs/hospitals.md) 逐家加入。介面以長輩為主要讀者設計：大字、口語、按鈕少而大。

**設定步驟請看 [SETUP.md](SETUP.md)。**

## 設計重點

- **標準函式庫，零外部依賴**。`ThreadingHTTPServer` + `sqlite3` + `urllib`，跟這台機器上的 `stock-dashboard` 同一套做法。`python3 -m bot.server` 就能跑。
- **查詢免費，推播才計費**。LINE 免費方案每月 200 則且不能加購，但只算主動推播；用 replyToken 回覆不計。所以所有查詢走 reply，額度只花在到號提醒（每次看診最多 2 則）。
- **「前面還有幾人」是數出來的，不是減出來的**。掛號號碼跳號很嚴重（實測某診 1–94 之間只有 42 個號），用「我的號碼 − 目前燈號」會高估兩倍以上。
- **身分證用完即丟**。查完只留下診間號與看診號，證號不進資料庫、不進日誌、不進 traceback。schema 裡沒有任何欄位放得下它。身分證查詢只開放給中國醫新竹，不擴展到其他醫院。
- **回診和領藥提醒是唯一的個人資料**：誰、哪天、看哪一診。只存這些，不存病名、藥名，`刪除我的資料` 可以全部刪掉。
- **對醫院客氣**。醫院跑的是 Apache 2.2 / CentOS 6。全程單一連線、每個請求間隔 1.2 秒、同一診間的結果共用快取；沒有訂閱或不在門診時段時，完全不發請求。

## 模組

| 檔案 | 職責 |
|---|---|
| `bot/fetch.py` | 唯一對醫院開 socket 的地方：每家醫院各自一次一個請求、請求之間保持間隔 |
| `bot/hospitals/` | 每家醫院一個介接模組：組請求網址、解碼、把頁面解析成統一格式；`__init__.py` 是註冊表 |
| `bot/waiting.py` | 跨醫院共用的排隊計算：前面還有幾人 |
| `bot/estimate.py` | 從門診進度歷史算出「大約再幾分鐘」 |
| `bot/watcher.py` | 背景輪詢與到號推播（含兩次確認防誤報），也負責跑回診和領藥提醒 |
| `bot/reminders.py` | 回診和領藥提醒：純日期計算，不需要連醫院 |
| `bot/convo.py` | 對話：判斷是哪家醫院、解析指令 |
| `bot/flex.py` | 大字卡片 |
| `bot/line_api.py` | 簽章驗證、reply、push（唯一控管推播額度的地方）|
| `bot/directory.py` | (醫院, 診間, 時段) → 醫師 目錄，供醫師姓名查詢 |
| `bot/server.py` | webhook 前端 |
| `bot/admin.py` | 白名單、狀態、刪除資料的 CLI |

## 測試

```bash
python3 -m unittest discover -s bot -t .
```

離線執行，不碰網路。`fixtures/` 存的是真實的 **Big5 位元組**（不是字串）— 存成字串的話就永遠測不到編碼那一段，而編碼正是這個專案三個已知陷阱裡的兩個。
