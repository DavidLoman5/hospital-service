# 醫院介接調查紀錄

每家醫院的看診進度系統都不一樣。寫介接模組之前，先在**門診時間內**調查清楚，記在這裡。原始回應的**位元組**（不是複製貼上的文字）要存到 `fixtures/<醫院 id>/`，這樣測試才測得到編碼那一段。

## 每家醫院要記錄的項目

| 項目 | 說明 |
|---|---|
| 進度頁網址 | 使用者會打開的頁面 |
| 實際請求 | 真正回傳資料的網址和參數。注意 form 的 action 可能被 JS 改寫，中國醫就是這樣，要看瀏覽器開發者工具 Network 分頁 |
| 編碼與格式 | Big5、UTF-8、HTML 還是 JSON |
| 有沒有號碼名單 | 有每一號的狀態（`has_ticket_list = True`），還是只有目前燈號 |
| 狀態用詞 | 對應到 `waiting.py` 的四種狀態：未報到、已報到、保留、完成 |
| 診間號格式 | 純數字、英數混合，還是科別加診別 |
| 時段與時間 | 上午、下午、晚上各是幾點到幾點 |
| 門診列表頁 | 有沒有一頁列出當天所有診（有的話設 `has_listing = True`，就不用逐診探測）|
| 同體系分院 | 分院是否共用同一套系統（共用的話一個模組可以涵蓋）|
| 使用條款 / robots | 有無禁止自動查詢的條款 |
| 伺服器 | 回應標頭裡的伺服器資訊，用來判斷請求間隔要設多寬鬆 |

## 介接模組的骨架

```python
# bot/hospitals/<id>.py
from bot.hospitals.base import Adapter

class Example(Adapter):
    id = "example"
    name = "某某醫院新竹分院"
    short = "某某新竹"          # 按鈕和標題用，越短越好
    aliases = ("某某",)          # 使用者可能打的名字
    has_ticket_list = True
    sessions = {"1": ("08:30", "12:00"), "2": ("13:30", "17:00"), "3": ("18:00", "21:00")}
    room_hint = "診間號碼，例如 7"

    def normalize_room(self, text): ...      # 不合法就丟 validate.Invalid
    def _fetch_room(self, room, session): ... # 回傳 waiting.py 描述的統一格式
    def room_url(self, room, session): ...
```
